ZYNERGY

Healthcare Backoffice System Testing

ZYNERGY is a healthcare backoffice system developed as part of an academic project. Testing covered nine core features (Login, Create Allergy, Create Menu, and six reminder/content management features) through manual functional testing on the UI and API testing via Postman.

My Role

Software Testing · Team of 3

Collaborated with two team members throughout the testing process. Testing responsibilities were divided based on system features, while test case preparation, execution, API testing, result analysis, and documentation were carried out collaboratively.

Methodology

Testing Approach

Manual Functional Testing

Tested system functionality by executing predefined test cases and comparing actual results with expected results.

Example: ZYNERGY-MENU-01
Scenario
Add a new food menu with a valid name, favorite, and allergy selection, then click Create
Expected
Data is saved and shown in the food menu list
Result
PASS

API Testing

Tested API endpoints using Postman to verify request handling and response behavior.

Black Box Testing

Tested system functionality based on input and expected output without examining the internal implementation of the system. Captured directly in the test case report below.

Equivalence Class Partitioning (ECP)

Divided input values into valid and invalid equivalence classes to identify potential input validation issues.

Example: Login feature
InputCategoryExpected
Registered email + correct passwordValid classAccepted, redirected to system
Unregistered emailInvalid classRejected, error shown
Empty email & passwordInvalid classRejected ("Please fill out this field")

Boundary Value Analysis (BVA)

Tested values around defined input boundaries to identify validation issues.

Example: Meal Reminder, Meal Minute field (TC34)
Minimum (0) → Boundary (59) → Tested: 60 → Rejected

The Meal Minute field only accepts 0–59. Input of 60 correctly triggered a validation error.

Decision Table

Tested different combinations of conditions and expected outcomes using a decision table.

Findings

Defects Found

Input Validation Issue

The system accepted special-character input in several text fields (allergy name, menu name, meal name, article title, user name) that should have been rejected. (ZYNERGY-MENU-05)

Duplicate Data

The system allowed a duplicate allergy entry to be submitted even though the same entry already existed in the list. (TC10)

Data Saving Issue

The interface showed a "Created" success pop-up for a new Light Activity Reminder, but the Activity Name field was not actually saved. (TC21)
